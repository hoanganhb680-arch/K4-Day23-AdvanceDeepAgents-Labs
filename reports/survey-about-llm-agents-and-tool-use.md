# LLM Agents and Tool Use: A Survey

## TL;DR
- LLM agents are systems that sense their environment, make decisions, and take actions, with tool use as one of the core action channels; the field has consolidated around perception-reasoning-action loops and modular frameworks (Profile, Memory, Planning, Action) [1][2][3].
- Seminal methods — ReAct's interleaved reasoning-and-acting, Toolformer's self-supervised API learning, and retrieval-augmented function calling (Gorilla, ToolLLM) — established the canonical patterns for grounding LLMs in external tools [4][5][6][7].
- Tool-use and agent benchmarks show a persistent and large gap between models and humans: WebArena best agent 14.41% vs humans 78.24%, OSWorld best model 12.24% vs humans 72.36%, GAIA GPT-4+plugins 15% vs humans 92% [8][9][10].
- The field has moved from single-agent prompting to multi-agent frameworks (AutoGen, MetaGPT, ChatDev), agentic workflows (Reflexion, Tree of Thoughts), computer-use and browser agents, and standardized tool protocols such as the Model Context Protocol (MCP) [11][12][13][14][15].
- Open problems dominate: failures compound nonlinearly with task length, prompt injection remains a critical vulnerability (e.g., 24% attack success against ReAct-prompted GPT-4), benchmarks saturate, and cost/token efficiency and governance are unresolved [16][17][18][19][20].

## Background
An LLM agent is an artificial entity that senses its environment, makes decisions, and takes actions, with the LLM acting as the "brain" that performs memory, reasoning, and planning, while perception extends to multimodal input and action includes textual output, tool use, and embodied action [2]. Surveys formalize this as a loop of perception, thinking/deciding, and acting, with feedback from the environment [2][3]. A widely used construction framework decomposes agents into four modules — Profile, Memory, Planning, and Action — where Action includes external tool calls [1]. Tool use matters now because it is the primary mechanism for grounding LLMs in up-to-date, verifiable, and executable information: it lets models query knowledge bases, call APIs, manipulate files, and operate software and web environments, which is what turns a text generator into an agent that can complete real tasks [4][5][6][21]. The field has grown rapidly since 2023, with dedicated surveys synthesizing hundreds of works and identifying tool use, planning, memory, and multi-agent coordination as the four component pillars of agent design [3][22].

## Foundations: reasoning, acting, and tool-augmented LLMs
The canonical pattern for tool use in LLM agents is ReAct, which interleaves reasoning traces with task-specific actions: reasoning helps induce, track, and update action plans and handle exceptions, while actions interface with external sources such as a Wikipedia API [4]. On HotpotQA and FEVER, ReAct reduces hallucination and error propagation compared with chain-of-thought prompting, and on ALFWorld and WebShop it beats imitation and reinforcement-learning baselines by absolute success rates of 34% and 10% using only one or two in-context examples [4]. Later work formalizes the ReAct process as a multi-turn trajectory of interleaved reasoning chains and actions and shows that agents exhibit significant uncertainty, with identical tasks yielding divergent trajectories [23].

Toolformer introduced self-supervised tool learning: the model learns to decide which APIs to call, when, with what arguments, and how to incorporate results into next-token prediction, requiring only a handful of demonstrations per API [5]. A 6.7B GPT-J model trained this way with tools such as a calculator, Q&A system, search engines, translation, and calendar substantially improves zero-shot performance across downstream tasks and is often competitive with much larger models [5].

Function calling and tool-augmented training scaled these ideas. ToolLLM built ToolBench from 16,464 real RESTful APIs across 49 categories from RapidAPI Hub, with ChatGPT-generated instructions covering single- and multi-tool scenarios, and trained ToolLLaMA using a depth-first-search decision tree (DFSDT) that outperforms ReAct-style search and generalizes to unseen APIs [6]. Gorilla fine-tuned a LLaMA model with Retriever-Aware Training on APIBench (~1,600 ML APIs from HuggingFace, TorchHub, and TensorHub) and surpassed GPT-4 on writing API calls while reducing hallucination, adapting to test-time documentation changes via a document retriever [7]. API-Bank provided a runnable evaluation system with 73 API tools and 314 annotated tool-use dialogues, showing that a trained Lynx model surpassed Alpaca by more than 26 points and approached GPT-3.5 [24].

Orchestration frameworks turned these primitives into reusable agent loops. LangChain defines an Agent as the LLM deciding actions, Tools as the actions available, Memory as the mechanism pulling in previous events, and an AgentExecutor as the while-loop that runs until a stopping criterion; the stereotypical LangChain agent is based on ReAct [25]. AutoGPT adds retrieval-based memory over intermediate steps for long-running goals, while BabyAGI plans a sequence of actions up front and re-plans after each execution [25]. HuggingGPT uses ChatGPT as a controller that plans tasks, selects models from Hugging Face by function description, executes subtasks, and summarizes responses — an early LLM-as-orchestrator architecture [21]. OpenAI's function calling standardized the loop: tools are declared via JSON schema in the `tools` parameter, the model emits tool calls, the application executes them and returns outputs, and the loop repeats, with controls such as `tool_choice`, `strict: true` for schema adherence, and `tool_search` for deferred loading of rarely used tools [26].

## Benchmarks and evaluation of tool use and agents
Tool-use evaluation spans a spectrum from static API-call generation to interactive multi-turn agentic evaluation [27][28][29][30][31][32][33][34][35]. The Berkeley Function Calling Leaderboard (BFCL) has become the de facto standard for function calling: it evaluates serial and parallel calls across languages with an AST-based metric plus executable evaluation, and version 4 adds agentic multi-step, memory, and web-search categories [29][30][31]. On BFCL V4, Claude Opus 4.5 leads with ~77.5 overall accuracy, followed by Claude Sonnet 4.5 (~73.2), Gemini 3 Pro Preview (~72.5), GLM-4.6 (~72.4), and Grok 4.1 (~69.6), while GPT-4.1 scores ~54.0 and GPT-5.2 ~55.9 [29]. Early leaderboard findings showed parity between proprietary and open models on simple calls, with GPT-series pulling ahead on multiple and parallel calls [30]. The ICML 2025 BFCL paper concludes that state-of-the-art LLMs excel at single-turn calls, but memory, dynamic decision-making, and long-horizon reasoning remain open challenges [31]. Specialized models can beat general-purpose ones: NexusRaven-V2 (13B) surpassed GPT-4 by up to 7% on human-generated nested/composite function-calling cases [32], and APIGen showed that verifiable, diverse function-calling training data improves performance on the Berkeley Function-Calling Benchmark [35].

Interactive benchmarks measure agents in realistic environments. τ-bench introduced the pass^k reliability metric and simulated-user evaluation with database-state comparison; even gpt-4o succeeded on fewer than 50% of tasks and pass^8 under 25% in retail, showing that function-calling agents are inconsistent and poor at rule-following [27][28]. AgentBench tested 29 models across 8 interactive environments and found top commercial LLMs strong as agents but a significant disparity with open-source models of 70B parameters or less, with poor long-term reasoning, decision-making, and instruction following as the main failure causes [36][37]. WebArena provides a realistic web environment with fully functional sites in four domains; the best GPT-4-based agent achieved 14.41% end-to-end success versus 78.24% for humans [8][38]. GAIA's 466 real-world questions require reasoning, multimodality, web browsing, and tool use; humans score 92% versus 15% for GPT-4 with plugins [10][39]. SWE-bench contains 2,294 software-engineering problems from real GitHub issues; the best model at release (Claude 2) solved only 1.96% [40][41]. OSWorld, the first scalable real computer environment, has 369 tasks with execution-based evaluation; humans reach 72.36% versus 12.24% for the best model, which struggles with GUI grounding and operational knowledge [9][42]. ToolQA isolates external-tool QA from internal-knowledge QA with 13 specialized tools [33][43], and ToolAlpaca generated 3,938 tool-use instances from more than 400 real-world tool APIs, with fine-tuned 7B/13B models achieving generalized tool use comparable to GPT-3.5 [34][44].

Evaluation methodology centers on AST matching and executable verification (BFCL), database-state comparison (τ-bench), execution-based success (WebArena, OSWorld, SWE-bench), pass@k/pass^k reliability, and cost/latency tracking [27][28][29][30][31][40][9]. Criticisms are well documented: benchmark contamination inflates scores [45], static benchmarks saturate quickly (e.g., HumanEval improved from 26% to 90% over 24 months while industrial deployment rates barely moved) [46][47], 13 of 15 major agent benchmarks rely exclusively on binary success measures, none integrate safety/security into scoring, and none include cost-efficiency in the primary evaluation protocol [48]. Contamination, non-determinism, and execution cost form a "structural trilemma" that no prominent verified benchmark jointly controls [48]. Responses include live, continuously updated benchmarks (SWE-bench-Live, LiveBench, BFCL v2-v4) [29][46][47] and best-practice checklists such as the Agentic Benchmark Checklist [49].

## Multi-agent systems and agentic workflows
Multi-agent frameworks emerged in 2023 as the dominant paradigm for LLM agent collaboration. AutoGen frames multi-agent work as conversation, enabling human participation and automated complex workflows [13]. MetaGPT encodes Standardized Operating Procedures into prompt sequences to reduce cascading hallucinations from naively chained LLMs [11]. ChatDev guides specialized agents through a waterfall-model chat chain for design, coding, and testing [50]. AgentVerse draws on human group dynamics to dynamically adjust agent composition [51], and CAMEL studies autonomous cooperation of chat agents through role-playing [52]. Production platforms have since matured: LangGraph provides stateful, cyclic, graph-based orchestration with human-in-the-loop control [53], CrewAI offers role-based crews [54], and Microsoft Agent Framework is the unified successor to AutoGen and Semantic Kernel [54].

Agentic workflow patterns showed that verbal self-reflection and tree search substantially improve reasoning and coding. Reflexion reinforces language agents via linguistic feedback stored in an episodic memory buffer, achieving 91% pass@1 on the HumanEval coding benchmark, surpassing the previous state-of-the-art GPT-4 (80%) [12]. Tree of Thoughts generalizes chain-of-thought by exploring a tree of thoughts with self-evaluation, lookahead, and backtracking, raising Game-of-24 success from 4% (CoT) to 74% with GPT-4 [55]. Hugging Face's smolagents (successor to transformers.agents) popularized code-as-action agents, where the CodeAgent writes actions as executable Python code rather than JSON tool calls, improving performance by 2-7 points on GAIA, MATH, SimpleQA, and Frames [15].

## Computer-use, browser agents, and tool-use protocols
Computer-use agents moved from research benchmarks to products in late 2024 and early 2025. Anthropic shipped Claude computer use in October 2024, making Claude 3.5 Sonnet the first frontier model to offer computer use in public beta [56]. OpenAI shipped Operator, a Computer-Using Agent combining GPT-4o vision with RL-trained GUI interaction, scoring 38.1% on OSWorld, 58.1% on WebArena, and 87% on WebVoyager [57]. Benchmarks standardized evaluation: OSWorld has 369 tasks (humans 72.36% vs best model 12.24%) [9][58], WebArena has 812 long-horizon tasks [8][59], Mind2Web provides 2,350 tasks from 137 real websites [60], and Windows Agent Arena and BrowserGym support scalable OS and web agent evaluation [61][62]. OpenDevin is an open platform for generalist software-development agents that write code, use command lines, and browse the web [63].

Tool-use protocols consolidated around the Model Context Protocol (MCP), an open standard open-sourced by Anthropic in November 2024 for two-way connections between data sources (MCP servers) and AI applications (MCP clients), with pre-built servers for Google Drive, Slack, GitHub, Git, Postgres, and Puppeteer [14]. MCP was later adopted by OpenAI (plugins and API connectors) and Google Cloud, and it standardizes tool use to solve the "N x M" integration problem [64][14]. Security research on MCP analyzes the landscape, threat models, and server lifecycle, finding vulnerabilities and code smells in MCP servers [64].

## Reliability, safety, and open problems
Reliability is the central open problem. Failures in LLM agents compound nonlinearly with task length; strong sub-task performance does not translate to end-to-end success, and additional scaffolding does not consistently improve reliability [16]. A synthesis of 27 benchmark, taxonomy, and audit papers identifies six failure clusters: tool invocation and parameter errors, planning and constraint failures, long-horizon degradation from context accumulation, multi-agent coordination failures, safety and security failures, and measurement validity problems [16]. The "horizon gap" — the distance between single-step capability and reliable long-task completion — is documented in a survey of 1,547 papers, which finds that outcome-only signals grow uninformative as the horizon grows, driving a shift to trajectory-level diagnostics [65]. Reliability metrics systematically diverge from capability measures, with degradation patterns varying by domain and capability tier [66], and production-like stress evaluation (fault injection) is emerging as a complement to accuracy benchmarks [67].

Safety and security are acute concerns. Indirect prompt injection lets adversaries remotely compromise LLM-integrated applications by injecting prompts into data retrieved at inference time, with retrieved prompts acting as "arbitrary code" enabling data theft, worming, and denial of service [17]. The InjecAgent benchmark (1,054 test cases, 17 user tools, 62 attacker tools) shows that ReAct-prompted GPT-4 is vulnerable to indirect prompt injection 24% of the time, and a hacking-prompt reinforcement nearly doubles attack success [18]. Simple prompt injection can leak personal data observed by agents during banking tasks [68], skill-file attacks achieve up to 80% vulnerability in frontier models [69], and individually scanner-passing skills can be composed into attack chains that bypass per-skill scanners [70]. A 247-paper survey finds that prompt injection and tool-mediated control-flow hijacking dominate LLM-agent security research, while persistent state corruption and multi-agent propagation are emerging concerns, and existing defenses remain weakly compositional [71]. Prompt infection — self-replicating malicious prompts spreading silently between agents — requires new defenses such as LLM tagging [72]. Guardrail approaches such as ToolSafe detect and block unsafe tool invocations [73], and kill-chain canary analysis shows that prompt-injection resilience depends on architecture choices rather than model identity alone [74].

Cost, latency, and context limits constrain deployment. Agentic coding agents consume significantly more tokens than other LLM applications, with substantial variability and poor predictive accuracy for token usage [20]; iterative code review stages account for most computational costs, with input tokens dominating [75]. Hardware-aware metrics such as Prefill Token Equivalents correlate better with actual latency than raw token counts by accounting for KV-cache inefficiencies and long tool responses [76]. Tool Attention reduces per-turn tool token overhead by 95% via gated attention over tools, improving context utilization from 24% to 91% [77], and Probe&Prefill reduces unnecessary tool calls by 48% with minimal accuracy loss [78]. Memory management is a major research front: REMORY supplements textual summaries with learned soft memory tokens [79], Memex maintains compact context while storing full interaction details in an external database [80], and behavioral state decay — decision-relevant state buried in or pushed beyond the context window — can be mitigated by a proactive memory agent [81].

Evaluation gaps and governance remain unresolved. Benchmark saturation is widespread and driven by benchmark age and design choices [19]; after saturation, measuring beyond accuracy reveals insights about construct validity, efficiency, reliability, and human-agent collaboration [82]. AI agents pose governance challenges for the EU AI Act, revealing gaps between existing regulatory frameworks and autonomous capabilities [83], and decentralized AI creates a "governance vacuum" that existing frameworks cannot fill [84]. Liability issues in LLM-based agentic systems are analyzed from a principal-agent perspective [85], and proposals range from Policy-as-Prompt runtime guardrails [86] and runtime governance protocols [87] to blockchain-based infrastructure giving agents legal identity and payment capabilities [88]. Open questions include long-horizon planning and credit assignment, continual learning, grounding, and multi-agent coordination failure [16][65][89][90][91].

## Trends and open problems
Over the last two years the field has shifted from single-model prompting to systems: multi-agent frameworks, computer-use and browser agents, and standardized tool protocols such as MCP have moved from research to production [13][56][57][14][54]. Evaluation has shifted from static function-calling accuracy to interactive, execution-based, and reliability-focused benchmarks, with live benchmarks and best-practice checklists responding to contamination and saturation [29][46][47][49]. The most disputed area is reliability: while capability benchmarks improve rapidly, end-to-end success in realistic environments remains far below human performance, and outcome-only metrics are increasingly seen as uninformative for long-horizon tasks [8][10][9][65]. Safety research is converging on prompt injection and tool-mediated control-flow hijacking as the dominant threat, with defenses still weakly compositional [17][18][71]. Cost and token efficiency are emerging as first-class constraints for agentic deployment [20][76][77], and governance frameworks for autonomous agents are nascent, with no consensus on how to attribute responsibility in multi-agent and decentralized systems [83][84][85].
